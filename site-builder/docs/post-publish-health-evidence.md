# Post-publication health display evidence — 20 October 2026

## Defect and change
The Builder previously accepted any truthy health.diagnosis on a 2xx response, without correlating health.siteId or checking fields subsequently rendered with checks.map. A malformed successful response could crash rendering or claim a healthy website without public-render evidence. Concurrent health reads could let an older success or failure overwrite the latest result.

The client now requires HTTP200 without redirection, the requested site ID, bounded unique known checks, valid display fields/statuses/actions/timestamp, core backend/publication/domain/billing checks and an overall status matching the strongest check. Healthy additionally requires a public_render check. Action/incident reports without public-render evidence remain displayable. A local request version suppresses late older responses/failures, including delayed JSON parsing. Each new read clears displayed evidence while checking. Missing site/token performs no request. Existing GET only, no-store, redirect:error, FR/EN locale header, no automatic retry. The pure display reader grants no repair or account rights.
