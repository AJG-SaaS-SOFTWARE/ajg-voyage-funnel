# Builder publication confirmation — 20 October 2026

A remote publication acknowledged by `saveMySite(config, true, siteId)` previously remained dependent on Growth bookkeeping and browser-local persistence. Either follow-up could throw after publication and lead to a publication-failed message. The client now records published/saved state immediately after the repository resolves, keeps promoted media in the active config, and reports follow-up failures separately in French and English. A Growth failure does not prevent local persistence or the existing health check; browser storage failure does not erase remote confirmation.

Before repository acknowledgement, failures are described as unconfirmed. The UI recommends checking the public site and Health Center before retrying, without exposing raw provider errors or claiming that no server write occurred. This matters because the repository itself can fail after a site write during managed-domain or draft cleanup. No automatic publication retry is added. Local-only publication still requires local persistence to succeed.

The 18 behavioral tests extract and execute the actual `publish` handler through the TypeScript AST with synthetic dependencies. Sixteen fail against baseline `c44a700e04e196435239a218513e61ee26c4d3e2`; all pass with the patch. They cover FR/EN Growth/cache failures (including combined failure), acknowledgement before pending Growth completion, pre-write session/write/media failure, local-only failure, promoted assets and unchanged success/validation behavior. Injected domain-read/synchronous analytics exceptions exercise the defensive outer catch; they are not claims that the current implementations throw those errors.

This change does not prove public page rendering, managed-domain availability, email receipt, ordinary browser authentication or Checkout. It adds no deadline, durable replay protection, cross-tab exclusion, backend/database/auth/permission/schema/offer changes, paid inference or live charge. Publication receipts survive follow-up failures within the mounted page; remount persistence is not added. Existing post-publication health and server rights remain required.

Baseline main/release and latest production release were rechecked before work; #536/#537 and #554 are already delivered and must not be redeployed separately. The previous publication worktree was copied into an isolated branch without modifying its files. Historical #525/#526 and ordinary email-to-browser-to-payment proof remain separate launch blockers.
